# Лабораторная работа №3 — Генератор рецептов по фото холодильника

**Проект 5: «Рецепт по фото холодильника»**

**Выполнили студенты:** Финогеев, Радионов, Стаценко, Булохов

В рамках лабораторной работы разработано мультимодальное приложение, которое принимает на вход фотографию содержимого холодильника, продуктовой полки или витрины, распознаёт видимые продукты и генерирует 2–3 рецепта, которые можно приготовить из найденных ингредиентов.

Проект построен как пайплайн из двух основных этапов:

1. **VLM-распознавание продуктов** — мультимодальная модель анализирует изображение и формирует список продуктов.
2. **LLM-генерация рецептов** — языковая модель получает список ингредиентов и пользовательские фильтры, после чего генерирует рецепты в структурированном виде.

В приложении также предусмотрена ручная оценка качества: для тестовых изображений сравниваются ожидаемые продукты и продукты, найденные моделью, а также фиксируются пропуски и галлюцинации.

## Ход работы

Цель проекта — проверить, насколько мультимодальные модели подходят для практической задачи распознавания продуктов на фото и последующей генерации полезных кулинарных рекомендаций.

В ходе работы были выполнены следующие этапы:

1. **Подготовка тестового набора изображений**  
   Для проверки системы был собран набор из 10 изображений холодильников, продуктовых полок и витрин. Изображения различаются по освещению, наполненности, ракурсу и сложности сцены.

2. **Разработка пайплайна распознавания продуктов**  
   На первом этапе изображение передаётся в мультимодальную модель. Модель должна выделить только продукты, которые действительно присутствуют на фото, и вернуть их в удобном текстовом формате.

3. **Разработка генератора рецептов**  
   На втором этапе список продуктов передаётся в языковую модель. Модель формирует несколько рецептов, используя найденные ингредиенты как основу.

4. **Добавление пользовательских фильтров**  
   В приложение добавлены параметры, которые позволяют ограничить генерацию: вегетарианский вариант, время приготовления и сложность рецепта.

5. **Создание веб-интерфейса**  
   Для удобного использования реализован интерфейс на Streamlit. Пользователь может загрузить фото, выбрать фильтры и получить готовые рецепты.

6. **Оценка качества**  
   Для тестовых изображений проводится ручная проверка: какие продукты модель нашла правильно, какие пропустила и какие добавила ошибочно.

## Теория

### Мультимодальные модели

Мультимодальные модели, или VLM (Vision-Language Models), способны работать одновременно с изображениями и текстом. В данном проекте такая модель получает фотографию холодильника и возвращает список распознанных продуктов.

В отличие от обычной модели компьютерного зрения, которая часто решает задачу классификации или детекции объектов, VLM может сразу формировать текстовое описание сцены. Это удобно для задач, где результат должен быть передан дальше в языковую модель.

### Распознавание продуктов по изображению

Распознавание продуктов по фото является нетривиальной задачей, потому что продукты могут быть:

- частично закрыты другими объектами;
- находиться в прозрачной упаковке;
- быть мелкими или размытыми;
- находиться в дальнем углу холодильника;
- выглядеть похоже друг на друга, например зелень, салат, шпинат или разные виды соусов.

Поэтому результат VLM не всегда является абсолютно точным. Для практического применения важно не только получить список продуктов, но и оценить два типа ошибок:

- **пропуски** — продукт есть на изображении, но модель его не указала;
- **галлюцинации** — модель указала продукт, которого на изображении нет.

### Генерация рецептов с помощью LLM

Языковая модель получает список продуктов и формирует рецепты. Важно, чтобы рецепты были связаны именно с распознанными ингредиентами, а не строились на случайных продуктах.

Для повышения качества генерации используется структурированный промпт. Он задаёт модели требования к ответу:

- предложить 2–3 рецепта;
- учитывать список найденных продуктов;
- не добавлять много отсутствующих ингредиентов;
- указывать примерное время приготовления;
- описывать сложность;
- выводить список ингредиентов и пошаговое приготовление.

### Роль фильтров

Фильтры делают систему более полезной для пользователя. В проекте предусмотрены следующие ограничения:

| Фильтр | Назначение |
|--------|------------|
| Вегетарианское блюдо | Исключает мясные и рыбные рецепты |
| Время приготовления | Помогает получить быстрые или более сложные блюда |
| Сложность | Позволяет выбрать простой, средний или сложный рецепт |

## Методика оценки

Для оценки качества используется файл `data/eval_expected.csv`, где вручную указываются ожидаемые продукты для каждого изображения.

Скрипт `evaluate.py` сравнивает результат модели с ручной разметкой и сохраняет итоговую таблицу в `outputs/eval_results.csv`.

Оценка выполняется по следующим критериям:

| Критерий | Что показывает |
|---------|----------------|
| Найденные продукты | Список продуктов, которые модель указала по фото |
| Ожидаемые продукты | Ручная разметка продуктов на изображении |
| Пропущенные продукты | Объекты, которые есть на фото, но отсутствуют в ответе модели |
| Придуманные продукты | Объекты, которых нет на фото, но модель их добавила |
| Полезность рецептов | Насколько рецепты можно реально приготовить из найденных ингредиентов |
| Соответствие фильтрам | Учитывает ли модель ограничения по времени, сложности и типу блюда |

Для лабораторной работы важна не только итоговая точность, но и анализ ошибок. Поэтому результаты рассматриваются вручную: проверяется, какие категории продуктов модель распознаёт уверенно, а какие вызывают затруднения.

### Типичные ошибки распознавания

В ходе тестирования были выявлены типичные проблемы, характерные для VLM при работе с фотографиями холодильника:

1. **Пропуск мелких объектов**  
   Модель может не заметить небольшие упаковки, банки или продукты на заднем плане.

2. **Обобщение похожих продуктов**  
   Например, разные виды зелени могут распознаваться просто как «зелень» или «салат».

3. **Ошибки на частично закрытых продуктах**  
   Если продукт перекрыт дверцей холодильника, контейнером или другим объектом, модель может его не указать.

4. **Галлюцинации типичных продуктов**  
   Иногда модель добавляет в список продукты, которые часто встречаются в холодильнике, но не видны на конкретном изображении.

5. **Проблемы с упаковками без читаемой маркировки**  
   Если товар находится в непрозрачной упаковке, модель может определить только общий тип продукта.

### Качество рецептов

Сгенерированные рецепты в целом соответствуют найденному набору продуктов. Наиболее качественные результаты получаются, когда на фото хорошо видны базовые ингредиенты: овощи, фрукты, яйца, молочные продукты, зелень, мясо или готовые продукты в контейнерах.

При неполном распознавании продуктов рецепты становятся более общими. Например, если модель распознала только «овощи» и «зелень», она может предложить салат или овощную закуску без точной детализации ингредиентов.

## Ограничения проекта

Несмотря на работоспособность пайплайна, у решения есть несколько ограничений:

1. **Нет точной детекции количества продуктов**  
   Модель может определить, что на фото есть яйца или яблоки, но не всегда корректно посчитает их количество.

2. **Нет гарантии свежести продуктов**  
   По фотографии сложно надёжно определить срок годности или свежесть продукта.

3. **Ошибки при плохом освещении**  
   Тёмные, размытые или пересвеченные фотографии ухудшают качество распознавания.

4. **Сложность с закрытыми упаковками**  
   Если продукт находится в непрозрачном контейнере, модель может только предположить содержимое.

5. **Рецепты требуют пользовательской проверки**  
   Система предлагает идеи, но пользователь должен самостоятельно оценить наличие ингредиентов, аллергенов и безопасность блюда.

## Возможные улучшения

В дальнейшем проект можно улучшить следующими способами:

1. **Добавить более строгую валидацию продуктов**  
   Например, просить модель возвращать уровень уверенности для каждого продукта.

2. **Разделить продукты на категории**  
   Овощи, фрукты, молочные продукты, мясо, напитки, соусы, готовые блюда.

3. **Добавить базу рецептов**  
   Вместо генерации рецептов полностью с нуля можно искать подходящие рецепты в базе, а LLM использовать для адаптации.

4. **Добавить режим уточняющих вопросов**  
   Если модель не уверена, она может спросить пользователя: «Это йогурт или сметана?».

5. **Сохранять историю запросов**  
   Это позволит сравнивать результаты и отслеживать улучшение качества.

6. **Увеличить тестовый набор**  
   Для более надёжной оценки можно собрать 50–100 изображений с ручной разметкой.

7. **Добавить автоматические метрики**  
   Можно рассчитывать precision, recall и F1-score для распознавания продуктов.

Проект демонстрирует практическое применение связки VLM + LLM: первая модель извлекает информацию из изображения, а вторая преобразует её в полезный текстовый ответ.

Наиболее сильная сторона системы — удобный пользовательский сценарий: достаточно загрузить фото, и приложение автоматически предлагает варианты блюд. Такой подход может быть полезен для бытовых задач, планирования питания и снижения пищевых отходов.

Основная проблема проекта — качество распознавания продуктов. Ошибки VLM напрямую влияют на рецепты: если продукт пропущен или придуман, итоговый ответ может стать менее точным. Поэтому для дальнейшего развития важно улучшить этап распознавания и добавить более строгую проверку списка ингредиентов.

В целом поставленная задача выполнена: разработан пайплайн, реализован веб-интерфейс, подготовлен тестовый набор изображений и предусмотрена оценка качества результатов.
