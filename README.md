# Лабораторная работа №3 — Генерация рецептов по фотографии холодильника с помощью мультимодальной модели

Выполнили студенты группы 459м: Лягушин Федор, Возиянов Лев, Эмин Акерма, Беналлал Абдель-Малек.

В рамках лабораторной работы был разработан прототип приложения, которое анализирует фотографию холодильника, продуктовой полки или отдельных продуктов, распознаёт доступные ингредиенты и на их основе генерирует несколько рецептов.  
Для работы используется мультимодальная модель через Groq API, а также отдельный сценарий оценки качества распознавания продуктов.

## Ход работы

В ходе выполнения лабораторной работы был реализован полный пайплайн обработки изображения и генерации результата:

1. Пользователь загружает фотографию холодильника, полки или набора продуктов.
2. Мультимодальная модель анализирует изображение и определяет продукты.
3. Полученный список ингредиентов передаётся языковой модели.
4. Модель генерирует 2–3 рецепта на основе найденных продуктов.
5. Пользователь может настроить фильтры:
   - вегетарианский режим;
   - время приготовления;
   - сложность рецепта;
   - количество порций.
6. Результат можно сохранить в папку `outputs`.
7. Для проверки качества распознавания используется Eval-набор из 10 фотографий и файл ручной разметки `data/eval_expected.csv`.

Главная цель работы — получить практический опыт работы с мультимодальными моделями, которые способны обрабатывать не только текст, но и изображения.

## Теория

### Мультимодальные модели

Мультимодальные модели — это модели искусственного интеллекта, которые могут работать сразу с несколькими типами данных.  
В данной лабораторной работе модель получает на вход изображение и возвращает текстовое описание найденных продуктов.

В отличие от обычных языковых моделей, которые анализируют только текст, мультимодальная модель способна понимать визуальное содержимое фотографии. Это позволяет использовать её для задач компьютерного зрения без обучения собственной нейросети с нуля.

### Vision-модель

Vision-модель используется для распознавания продуктов на изображении.  
Она получает фотографию, анализирует объекты на ней и формирует структурированный список ингредиентов.

Пример входных данных:

```text
Фото холодильника или продуктовой полки
````

Пример результата:

```text
молоко, яйца, сыр, помидоры, огурцы, курица
```

### Генерация рецептов

После распознавания продуктов список ингредиентов передаётся языковой модели.
На основе этого списка модель генерирует несколько рецептов, которые можно приготовить из имеющихся продуктов.

При генерации учитываются пользовательские ограничения:

* максимальное время приготовления;
* сложность блюда;
* количество порций;
* необходимость вегетарианского рецепта.

### Оценка качества распознавания

Для оценки качества была подготовлена ручная разметка изображений.
Скрипт `evaluate.py` сравнивает продукты, указанные вручную, с продуктами, которые нашла модель.

Используются следующие метрики:

* `precision` — точность, то есть доля правильно найденных продуктов среди всех найденных моделью;
* `recall` — полнота, то есть доля найденных продуктов среди всех продуктов из ручной разметки;
* `f1_score` — среднее гармоническое между precision и recall.

Также отдельно анализируются:

* продукты, которые модель нашла правильно;
* продукты, которые модель пропустила;
* продукты, которые модель ошибочно добавила.

## Настройка Groq API

Для работы проекта требуется API-ключ Groq.

Необходимо создать файл `.env` или заполнить уже существующий шаблон:

```env
PROVIDER=groq
GROQ_API_KEY=твой_ключ
GROQ_MODEL=meta-llama/llama-4-scout-17b-16e-instruct
GROQ_RECIPE_MODEL=meta-llama/llama-4-scout-17b-16e-instruct
```

Основной параметр, который нужно заполнить:

```env
GROQ_API_KEY=твой_ключ
```

Без API-ключа приложение не сможет обращаться к модели.

## Запуск веб-приложения

Для запуска интерфейса используется команда:

```bash
streamlit run app.py
```

После запуска приложение откроется в браузере.

Порядок работы:

1. Загрузить фотографию холодильника или продуктов.
2. Нажать кнопку распознавания продуктов.
3. Проверить список найденных ингредиентов.
4. Указать дополнительные фильтры.
5. Сгенерировать рецепты.
6. При необходимости сохранить результат.

## Запуск через терминал

Пример запуска обработки изображения:

```bash
python main.py --image data/eval_images/fridge_01.jpg --time 30 --difficulty легко --servings 2
```

Пример запуска с вегетарианским фильтром:

```bash
python main.py --image data/eval_images/fridge_02.jpg --vegetarian --time 20 --difficulty легко
```

Такой режим удобен для тестирования без веб-интерфейса.

## Eval на 10 изображениях

Для оценки качества используется набор из 10 фотографий:

```text
data/eval_images/fridge_01.jpg
data/eval_images/fridge_02.jpg
...
data/eval_images/fridge_10.jpg
```

Ручная разметка хранится в файле:

```text
data/eval_expected.csv
```

Запуск оценки:

```bash
python evaluate.py --expected data/eval_expected.csv --images-dir data/eval_images --out outputs/eval_results.csv
```

После выполнения создаётся файл:

```text
outputs/eval_results.csv
```

В нём содержатся результаты сравнения ручной разметки и ответа модели.

## Анализ ошибок

Основные типы ошибок:

1. **Пропуск продуктов**
   Модель не всегда замечает небольшие или частично закрытые продукты.

2. **Ошибочное добавление продуктов**
   Иногда модель предполагает наличие типичных продуктов, даже если они не видны на изображении.

3. **Проблемы с качеством изображения**
   Если фото тёмное, размытое или перегруженное деталями, качество распознавания снижается.

4. **Сложность сцены**
   Чем больше продуктов находится на фото, тем выше вероятность ошибки.

5. **Похожие продукты**
   Модель может путать продукты с похожим внешним видом, например разные виды овощей, упаковок или молочных продуктов.

### Выводы по Eval
По результатам сравнения ручной разметки с ответами модели видно, что модель частично справляется с распознаванием продуктов, но качество нестабильное. Средние значения метрик составили:

| Метрика   | Среднее значение |
| --------- | ---------------: |
| Precision |            0.370 |
| Recall    |            0.364 |
| F1-score  |            0.364 |

Это означает, что модель находит часть правильных продуктов, но одновременно часто пропускает реальные продукты и добавляет лишние.

Из 77 продуктов, указанных вручную, модель совпала с ручной разметкой по 36 позициям. При этом было 41 пропущенное наименование и 38 лишних наименований. Лучше всего модель сработала на изображениях fridge_08.jpg и fridge_09.jpg, где было много хорошо видимых фруктов и овощей. Хуже всего результат получился на fridge_05.jpg и fridge_10.jpg, где модель почти ничего не распознала.

Также часть ошибок связана не только с качеством модели, но и со строгим сравнением названий. Например, помидоры и томаты, салат и листовой салат, лайм и лаймы считаются разными продуктами, хотя по смыслу это близкие совпадения. Из-за этого реальные показатели качества могут быть немного выше, чем формальные метрики.

Итоговый вывод: модель подходит для прототипа приложения и может использоваться для примерного определения содержимого холодильника, но для точного распознавания продуктов требуется улучшение нормализации названий, обработка синонимов и, возможно, дополнительная ручная проверка результата перед генерацией рецептов.

## Выводы по лабораторной работе

В ходе лабораторной работы был разработан прототип приложения для генерации рецептов по фотографии холодильника или набора продуктов.
Проект демонстрирует практическое применение мультимодальных моделей: изображение используется как входные данные, после чего модель распознаёт продукты и передаёт их языковой модели для генерации рецептов.

Был реализован как веб-интерфейс на Streamlit, так и запуск через терминал.
Также был подготовлен Eval-набор из 10 фотографий с ручной разметкой, что позволило оценить качество распознавания с помощью метрик precision, recall и F1-score.

Средние значения метрик показали, что модель способна находить часть продуктов, но качество распознавания зависит от сложности изображения, освещения, количества объектов и качества фотографии.
Основные ошибки связаны с пропуском мелких продуктов и добавлением лишних ингредиентов.

Несмотря на это, проект показывает, что мультимодальные модели можно использовать для создания прикладных сервисов, где пользователь загружает изображение и получает полезный текстовый результат. В дальнейшем качество можно улучшить за счёт более точных промптов, предварительной обработки изображений, увеличения тестового набора и ручной проверки найденных ингредиентов перед генерацией рецептов.
